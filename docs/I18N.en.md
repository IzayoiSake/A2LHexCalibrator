# Internationalization maintenance

[简体中文](I18N.md) | English

1. Add the same key to `locales/zh_CN.json` and `locales/en_US.json` under the Python package. Translate values, not keys.
2. Call `self.tr("language.menu")` from UI. Use named placeholders such as `{p0}` and pass `p0=count`. Format addresses or precision-sensitive values before translation so language cannot change numerical semantics.
3. TranslationService handles resource I/O without Tk. Each window owns its language state. Never translate parameter names, addresses, enum content or raw diagnostics automatically.
4. Both languages are embedded in the EXE. Optional `locales/zh_CN.json` and `locales/en_US.json` next to the EXE override known keys. Values must be nonempty strings with identical placeholder signatures. Missing files, invalid JSON and invalid entries fall back to bundled text. Restart after editing.
5. The `language` preference shares `%APPDATA%/A2LHexEditor/shortcuts.json` with existing shortcuts. Legacy files need no migration. Switching preserves the session, edits and undo history, but is deferred while a task/dialog is active (choose again afterwards).
6. A new language requires a catalog plus updates to LANGUAGES and menu labels. Test key/placeholder parity, English keyboard editing, filter preservation and button visibility.
7. Python package-data and PyInstaller `--collect-data a2l_hex_calibrator` include the resources. Smoke-test both languages without external catalogs before release.

Windows native dialog buttons follow OS language; low-level parser diagnostics retain their original wording. A2L descriptions and enum labels are supplied by the file.
